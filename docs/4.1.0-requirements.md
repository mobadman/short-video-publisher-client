# 短视频批量发布助手 4.1.0 需求文档

- 文档状态：已实现，等待真实发布批次验证
- 基线版本：4.0.3
- 目标版本：4.1.0
- 日期：2026-09-17
- 作者：SquiD

## 1. 版本目标

4.1.0 在不改变现有飞书只读拉取、Chrome Profile、发布按钮单击保护、失败续跑和发布 ID 同步链路的前提下，完成三类升级：

1. 根据真实发布日志继续压缩抖音和视频号的单条发布耗时，优先解决视频号发布偏慢的问题。
2. 增加可视化素材库管理，通过表单为产品型号增加文案、Tag、封面和商城商品短标题。
3. 为抖音商城工作区增加“无本地封面时使用视频首帧”的正式工作流，将该情况显示为黄色可发布警告，而不是红色阻断错误。

本版本不是发布链路重写。所有优化必须保留现有安全条件，并能按功能开关回退到 4.0.3 的稳定策略。

## 2. 现状与问题

### 2.1 发布效率基线

最近稳定批次的日志表现如下：

| 链路 | 当前基线 | 已确认的主要卡点 |
| --- | --- | --- |
| 抖音主页号 | 中位数约 28.4 秒/条，P90 约 39.1 秒 | 正文与 Tag 输入约 9.7 秒；横封面确认存在长尾 |
| 视频号 | 约 67–74 秒/条 | 当前报告没有阶段计时，只能确认整体约为抖音的两倍 |
| 飞书素材拉取 | 最近 5 条约 66 秒 | 每条附件“发起下载”约 10.5 秒，仍受串行页面操作影响 |

抖音上一轮优化已经缩短了发布页打开、视频选择、上传等待和结果确认。下一阶段应聚焦输入方式和封面长尾。视频号必须先补齐分阶段计时，再根据数据逐项启用安全快路径。

### 2.2 素材维护现状

素材库目前通过本地目录和文本文件维护：

```text
本地素材库
├─ 文案库/产品型号.txt
├─ Tag库/产品型号.txt
├─ 封面库/产品型号/*.{jpg,jpeg,png}
└─ 商品短标题库/产品型号.txt
```

该结构稳定且已经被计划生成链路使用，但人工直接编辑目录和文本文件门槛较高，容易产生型号命名错误、Tag 格式错误、重复内容或只写入部分素材的问题。

### 2.3 商城封面误判

当前所有工作区都把“封面缺失”记入阻断问题：

```text
封面缺失 → problems 增加“封面” → ready=false
→ 表格整行标红 → 勾选批次无法开始发布
```

商城视频的实际工作流不同：允许不上传本地封面，直接使用视频首帧。因此，仅缺少封面的商城计划项不应被判为不可发布。

## 3. 设计原则与边界

- 飞书数据继续只读，不向飞书回写素材、状态或发布 ID。
- 继续使用当前工作区隔离和应用专用持久化 Chrome Profile，兼容 3.1.2 系列已有 Profile。
- 不使用平台未公开接口，不增加多标签页并行发布，不绕过扫码或安全验证。
- 发布按钮仍然只点击一次；结果不明确时停止并交由人工核对，禁止自动重试。
- 新素材录入界面只作为现有素材库的安全写入层，不改变计划生成时按产品型号匹配素材的逻辑。
- 商城首帧策略只适用于 `douyin-commerce` 工作区；抖音主页号和视频号缺少封面时仍为红色阻断问题。
- 任何其他缺失与“封面缺失”同时出现时，阻断问题优先，整行仍显示红色。

## 4. 功能一：商城视频首帧封面策略

### 4.1 状态模型

计划项从单一的 `problems` 状态扩展为：

```js
{
  problems: [],       // 阻断发布的问题
  warnings: [],       // 不阻断发布、但需要在复核页可见的提醒
  ready: true,        // 仅由 problems 是否为空决定
  coverMode: "video-first-frame",
  coverPath: null
}
```

`coverMode` 支持以下值：

| 值 | 含义 | 发布行为 |
| --- | --- | --- |
| `library-cover` | 从素材库匹配到本地封面 | 执行现有竖封面和横封面上传 |
| `manual-cover` | 用户在编辑计划时手动选择封面 | 执行现有封面上传；文件失效时红色阻断 |
| `video-first-frame` | 商城视频不上传本地封面 | 不打开封面上传窗口，使用平台视频首帧策略 |

禁止仅根据 `coverPath === null` 推断封面策略。必须保存 `coverMode`，以区分“商城允许首帧”和“其他工作区真正缺失封面”。

### 4.2 计划生成规则

生成计划时按以下优先级判断：

```text
匹配到有效本地封面
→ coverMode=library-cover
→ 不产生封面问题或警告

未匹配到封面 + 商城工作区
→ coverMode=video-first-frame
→ 从阻断问题中移除“封面”
→ warnings 增加“未匹配本地封面，将使用视频首帧”
→ 只要没有其他 problems，ready=true

未匹配到封面 + 非商城工作区
→ problems 保留“封面文件不存在”
→ ready=false
```

若商城计划项同时缺少 Tag、商品链接或商品短标题，即使封面可使用首帧，仍然 `ready=false`，表格显示红色。

### 4.3 计划表视觉与交互

计划表状态优先级：

1. 有 `problems`：红色行，状态显示具体阻断原因，不允许进入发布。
2. 无 `problems` 但有 `warnings`：浅黄色行，状态显示“可发布 · 使用首帧”。
3. 无问题无警告：正常行，状态显示“完整”。

黄色行默认保持勾选并计入“可发布”数量，不要求用户额外确认。工作台准备度区域同时显示：

```text
7 / 8 可发布
其中 2 条将使用视频首帧
1 条存在阻断问题
```

用户点击“查看”时必须看到：

- 封面策略：视频首帧（商城默认）
- 本地封面：未匹配
- 发布影响：不会上传本地竖封面或横封面

商城计划项的编辑窗口增加封面策略：

- 使用视频首帧
- 选择本地封面

未匹配封面时默认选中“使用视频首帧”。用户手动选择封面后切换为 `manual-cover`。用户主动恢复“使用视频首帧”后，清空本批次的手动封面路径，但不删除素材库中的任何文件。

### 4.4 发布执行规则

发布层不能只依赖 `coverPath`：

- `library-cover` 或 `manual-cover`：封面文件必须存在，继续执行当前竖封面和横封面上传。
- `video-first-frame`：跳过本地封面上传，不打开封面弹窗，不触发 Windows 文件选择窗口。
- 视频完成平台处理后，优先检查发布页是否已有平台生成的封面预览；能读取时记录验证证据。
- 如果平台当前页面提供明确的“第一帧”选择入口，则显式选中并回读；如果平台只提供自动生成的默认视频封面，则保留默认状态，并在日志中记录“平台默认首帧策略”。
- 首帧策略本身不因无法读取预览而阻断发布，但页面明确提示“必须设置封面”时必须停止，不能擅自继续。

每条发布日志增加：

```text
封面策略：视频首帧（商城默认）
本地封面上传：已跳过
平台封面状态：已读取预览 / 平台默认 / 页面要求人工处理
```

### 4.5 旧计划兼容

计划结构升级为 schema version 3。读取 4.0.3 的 schema version 2 计划时：

- 商城计划项没有有效封面时，自动设置 `coverMode=video-first-frame`。
- 原“封面文件不存在”从 `problems` 移入 `warnings`。
- 其他问题保持原样。
- 非商城计划项不改变。
- 已处于 `verified` 或 `id-resolved` 的历史项只升级展示字段，不重新进入可执行队列。

## 5. 功能二：素材库表单管理

### 5.1 信息架构

侧边栏增加一级入口“素材库”，包含：

- 产品列表
- 新增产品
- 编辑产品
- 变更记录

产品列表以工作区为筛选条件，显示产品型号、文案数量、Tag 方案数量、封面数量、商品短标题数量和完整性状态。

### 5.2 新增与编辑表单

| 字段 | 规则 |
| --- | --- |
| 产品型号 | 必填；显示清洗后的实际文件名；检测不同原始型号映射到同一路径的冲突 |
| 目标工作区 | 可多选抖音主页号、抖音商城号、视频号；默认当前工作区 |
| 文案 | 以可增删的文案卡片维护，一张卡片代表一个现有文本行 |
| Tag 方案 | 每组最多 5 个；自动去除 `#`、空白和重复 Tag |
| 封面 | 支持多选或拖入 jpg、jpeg、png；显示缩略图、文件名、尺寸与重复状态 |
| 商品短标题 | 仅商城工作区显示；沿用现有长度和格式校验 |
| 保存方式 | 默认“追加并去重”；“替换该产品素材”需要二次确认 |

选择多个工作区时，默认复制同一套素材到各自独立素材库。可以展开“平台单独设置”覆盖特定平台的文案或 Tag。4.1.0 不建设跨工作区共享中央素材库，避免改变现有匹配和迁移边界。

### 5.3 完整性判定

表单保存前按目标工作区分别计算结果：

| 情况 | 主页号／视频号 | 商城号 |
| --- | --- | --- |
| 缺文案 | 红色阻断 | 红色阻断 |
| 缺 Tag | 红色阻断 | 红色阻断 |
| 缺封面 | 红色阻断 | 黄色提示“将使用视频首帧” |
| 缺商品短标题 | 不适用 | 红色阻断 |

因此，同一份没有封面的产品素材同时保存到主页号和商城号时，应明确显示：主页号不完整，商城号可发布但使用首帧。不能用一个总状态掩盖不同工作区的差异。

### 5.4 安全写入

保存必须采用暂存和原子提交：

1. 校验所有字段、目标路径和文件类型。
2. 校验目标目录没有符号链接或路径越界。
3. 文案、Tag 和短标题精确去重。
4. 对封面计算 SHA-256；相同内容跳过，同名不同内容自动追加序号。
5. 在临时目录写入全部文本和图片。
6. 所有工作区均准备成功后再提交正式文件。
7. 任一步失败则整体回滚，不留下半套素材。
8. 替换模式提交前创建可恢复备份。
9. 写入本地变更记录：时间、工作区、产品型号、操作模式、增加／跳过／替换数量和图片摘要。

保存完成后必须调用现有素材匹配逻辑进行自检，并展示实际匹配结果。保存动作不得自动改写已经生成的发布计划。

如果当前计划中存在相同产品型号，显示“重新匹配当前计划”入口。执行前预览受影响条目；只允许修改尚未发布且未锁定的计划项。

## 6. 功能三：视频号发布效率优化

### 6.1 分阶段可观测性

视频号日志增加以下计时：

- 进入发布页
- 发布 iframe 就绪
- 选择视频
- 填写正文
- 激活 Tag
- 上传及平台处理
- 填写短标题
- 设置定时并回读
- 设置封面
- 人工验证等待
- 点击发表
- 结果确认

同时记录：进入发布页采用直接地址还是首页回退、寻找 iframe 次数、扫码等待时间、发表按钮首次可用时间以及提交结果证据。

先使用原策略完成至少 2–3 个真实的 5 条批次，形成阶段基线，再判断各优化开关的收益。

### 6.2 安全快路径

- 第一条或当前页失效时允许从首页进入；后续条目优先直达发布页，失败后回退首页路径。
- 取消全局 `slowMo`，仅在实际需要的平台控件上等待。
- 用“上传框已挂载 + 编辑器可见”代替 `networkidle`。
- 正文整体写入并回读；Tag 使用短间隔逐个输入，每个 Tag 验证已形成平台标签。
- 缓存当前有效的发布 iframe，导航变化或 iframe 失效后才重新寻找。
- 人工验证改为识别已知遮罩和提示，不在每次上传轮询中遍历所有 frame 全文。
- 视频开始上传后，在控件可用的前提下填写正文、Tag、短标题、定时和封面。
- 最终发布前统一检查视频处理、字段回读、封面、定时和发表按钮状态。
- 提交后同时监听明确成功文案、明确失败文案、页面跳转和按钮消失；结果不确定时仍停止。

禁止多视频并发、多个发布标签页并发和不确定结果自动重试。

### 6.3 性能目标

| 阶段 | 目标 |
| --- | --- |
| 第一阶段 | 视频号中位数 45–55 秒/条，P90 不超过 65 秒 |
| 第二阶段 | 经验证上传期间填表安全后，中位数争取达到 35–45 秒/条 |
| 抖音主页号 | 中位数由约 28.4 秒降至 20–24 秒，且不增加封面或提交错误率 |

目标属于验收指标，不得通过删除回读、安全等待或结果确认来实现。

## 7. 功能四：抖音剩余性能优化

- 正文从全局慢速逐字输入改为整体写入，并校验最终文本。
- Tag 仍逐项触发平台识别，但降低按键间隔并校验成功数量。
- 为竖封面和横封面分别记录正常预览、裁剪弹窗、兼容观察和失败路径。
- 重点处理横封面 P90 长尾；无法读取成功信号时仍保留兼容观察，不删除现有安全兜底。
- 优化前后按相同视频数量、相近文件大小和同一网络环境比较，避免把网络波动误判为代码收益。

## 8. 非本版本范围

- 不改造飞书表格字段设计，不向飞书写入素材库内容。
- 不建设云端素材库或团队权限系统。
- 不支持多个抖音或视频号发布页面并发执行。
- 不自动生成文案、Tag、封面或商品短标题。
- 不改变现有发布 ID 同步和“一键打开本批次视频链接”功能。
- 飞书附件下载的进一步提速列入后续版本；4.1.0 只保留并完善现有下载计时。

## 9. 验收标准

### 9.1 商城首帧

1. 商城计划只缺封面时显示黄色，`ready=true`，默认勾选并允许发布。
2. 商城计划缺封面且缺 Tag 时显示红色，发布按钮阻止执行。
3. 主页号或视频号缺封面时继续显示红色并阻止执行。
4. 黄色行的查看和编辑入口能明确展示封面策略。
5. 使用首帧发布时不会打开封面弹窗和 Windows 文件选择窗口。
6. 发布报告能说明跳过本地封面的原因和平台封面状态。
7. 用户手动选择封面后，封面文件丢失必须变为红色，不能静默退回首帧。
8. 旧版商城计划加载后能正确迁移为黄色或红色，不改变已完成条目的执行状态。

### 9.2 素材库表单

1. 新增产品后，现有计划匹配函数能够直接读取生成的文案、Tag、封面和短标题。
2. 追加模式不会覆盖或重复已有内容。
3. 替换模式必须二次确认并产生可恢复备份。
4. 多工作区保存任一目标失败时全部回滚。
5. 型号路径冲突、非法图片、超过 5 个 Tag 和不合法短标题均在提交前阻止。
6. 商城素材缺封面显示黄色，其他工作区缺封面显示红色。
7. 保存素材不会静默修改当前发布计划。

### 9.3 发布性能与安全

1. 视频号报告包含全部分阶段耗时和结果证据。
2. 快路径可通过配置关闭并回退稳定路径。
3. 相同测试批次下达到第一阶段性能目标，或根据阶段日志给出不能达到的明确平台瓶颈证据。
4. 定时、正文、Tag、封面和商品配置回读正确率不得低于 4.0.3。
5. 不发生重复点击发表、重复发布或失败后自动重试。
6. 扫码验证出现时保持当前条目进度，验证完成后继续；超时后保存批次状态。
7. 未完成条目仍可续跑，已确认发布条目不会重复进入队列。

## 10. 测试矩阵

至少覆盖以下组合：

| 工作区 | 本地封面 | 其他素材 | 预期 |
| --- | --- | --- | --- |
| 抖音主页号 | 有 | 完整 | 正常可发布 |
| 抖音主页号 | 无 | 完整 | 红色阻断 |
| 抖音商城号 | 有 | 完整 | 正常可发布并上传封面 |
| 抖音商城号 | 无 | 完整 | 黄色可发布并使用首帧 |
| 抖音商城号 | 无 | 缺 Tag | 红色阻断 |
| 抖音商城号 | 手动封面后文件丢失 | 完整 | 红色阻断 |
| 视频号 | 有 | 完整 | 正常可发布 |
| 视频号 | 无 | 完整 | 红色阻断 |

真实发布验证至少包括：抖音主页号 5 条、抖音商城号有封面 3 条、抖音商城号首帧 3 条、视频号 3 个五条批次。所有真实测试继续使用指定测试账号或经人工确认的正式批次。

## 11. 推荐实施顺序

1. 升级计划 schema，拆分 `problems` 与 `warnings`，完成商城首帧规则和旧计划迁移。
