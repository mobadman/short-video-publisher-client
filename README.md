# 短视频批量发布助手 4.1.5

Windows 本地批量发布客户端，作者 **SquiD**。软件通过应用专用 Chrome Profile 读取飞书表格并登录发布平台，结合本地封面、文案、Tag 与商品配置生成发布计划，人工复核后执行定时发布。

4.1.5 沿用 3.1.2 的 `appId`、Electron `userData` 位置、账号 ID 与 `chrome-profiles` 目录结构，已经登录的 3.1.2 本地 Profile 可以直接复用。日常个人 Chrome 默认 Profile 不在自动化范围内。

## 当前能力

- 抖音主页号、抖音商城号和微信视频号发布；
- 多工作区、多账号及彼此独立的本地素材库；
- 飞书表格只读拉取、附件下载、登录检测及指定日期筛选；
- 1–44 条视频排期、计划查看与编辑、中断续发和发布 ID 同步；
- 本地封面、文案、Tag、商品链接和商品短标题管理；
- 飞书【AI标识】到抖音“内容由AI生成”的自主声明；
- TXT、CSV 发布记录，以及按飞书实际行排序的纯 ID 单列复制；
- 同步 ID 时保留每条抖音视频链接，并可在当前发布账号 Chrome 中一键打开本批次全部已同步视频；
- 预计耗时、下载进度、发布进度、准备度和下一发布时间仪表；
- 固定在窗口底部的发布授权与“复核并发布”操作区。

## 版本口径

项目在进入 GitHub 公开发布前经历了较长的本地验证期。为避免把测试包写成正式发行版，下文使用三种口径：

- **原型／内部测试**：有项目资料、源码快照或安装包，但没有公开 GitHub Release；
- **预发布**：GitHub Release 标记为 prerelease，用于架构迁移或现场验证；
- **正式版**：GitHub Release 标记为正式发布。

0.2.1 至 1.2.2 的本地构建快照保留在早期工程中；公开 GitHub Release 从 1.1.0 开始。没有出现的版本号（例如 3.0.9）从未形成可交付构建，因此不补写虚构记录。

## 从立项到 1.0：原型和测试阶段

### 原始 Agent Skill：流程立项

项目最早以 `douyin-scheduled-publisher` Agent Skill 立项，还不是桌面软件。这个阶段确立了后来一直保留的底层规则：一个账号绑定一个持久化 Profile；飞书和内容库只读；账号不符、素材缺失或页面结果不明确时立即停止；发布按钮只点击一次；正式批次限定为人工批准的指定日期素材；登录维护、账号切换、单条测试和正式批量发布四种模式互不混用。

这一阶段同时形成了排期、内容选择、批次校验、运行状态锁、测试任务校验和报告模板等脚本化流程，为后续桌面客户端提供了业务原型。

### 0.1.0：独立桌面验证器

0.1.0 将原 Skill 拆成独立的本地桌面项目，先验证“小号单条发布”，尚未启用生产飞书表格、8–20 条批量排期和正式账号发布。已经具备专用 Profile、文件格式／大小／SHA-256 校验、上海未来时间校验、账号唯一标识与昵称双重核验、干跑不提交、真实提交双重授权、重复视频指纹保护、运行锁、截图证据和 Markdown 报告。

## 4.1.4 实测效率

以下数据来自本地生产发布日志，用于描述当前工作流的实际耗时，不代表平台网络和页面响应始终保持相同速度：

## 当前发布确认规则

程序只在平台明确显示“发布成功”“提交成功”“作品发布成功”或“已提交审核”后，将当前视频标记为平台已确认提交并继续下一条。页面仅跳转、等待超时或出现失败提示都不会被当作成功，也不会自动重复点击发布。

作品管理不承担发布后的即时硬核验。批次完成后，可使用“同步视频 ID”从抖音个人主页核对作品并生成 ID 记录。

## 安全边界

飞书与在线素材始终只读；账号登录资料、下载缓存和发布日志只保存在用户本机，不进入仓库。任意网页结构、账号、素材或网络异常会停止当前任务并保留已完成进度。发布按钮每条视频只点击一次，结果不明确时禁止自动重试。

升级 4.1.5 不迁移、不删除 3.1.2 的账号 Profile，也不会删除现有用户本机已经保存的飞书链接。全新安装需要在每个工作区自行填写飞书表格地址。首次升级后应分别打开各工作区的飞书和发布平台 Chrome，确认登录检测正常，再用测试日期完成一次附件拉取与可删除的定时发布验证。
